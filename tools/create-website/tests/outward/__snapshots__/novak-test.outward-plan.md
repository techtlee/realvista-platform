## 15. Vercel env, production seed, deploy (`vercel-env`)

Backend env and deploy, then seed production once it is up, then the site env and deploy. Production secrets are new values in the production files, never the local dev ones.

```sh
cd "$CW_ROOT"
# Generate PAYLOAD_SECRET for production (created if missing, never overwritten, never shown)
cw secret-pipe --generate novak-test backend/.env.production.local PAYLOAD_SECRET
# Generate MAKLERI_ADMIN_PASSWORD for production (created if missing, never overwritten, never shown)
cw secret-pipe --generate novak-test backend/.env.production.local MAKLERI_ADMIN_PASSWORD
# Generate CLIENT_PASSWORD for production (created if missing, never overwritten, never shown)
cw secret-pipe --generate novak-test backend/.env.production.local CLIENT_PASSWORD
# Generate REVALIDATE_SECRET for production (created if missing, never overwritten, never shown)
cw secret-pipe --generate novak-test backend/.env.production.local REVALIDATE_SECRET
cd "$CW_ROOT/clients/backend-novak-test"
# Set DATABASE_URL on the backend project (production)
cw secret-pipe novak-test backend/.env.production.local DATABASE_URL | vercel env add DATABASE_URL production
# Set PAYLOAD_SECRET on the backend project (production)
cw secret-pipe novak-test backend/.env.production.local PAYLOAD_SECRET | vercel env add PAYLOAD_SECRET production
# Set PLATFORM_SUBDOMAIN_BASE on the backend project (production)
printf %s realvista.cz | vercel env add PLATFORM_SUBDOMAIN_BASE production
# Set R2_BUCKET on the backend project (production)
cw secret-pipe novak-test backend/.env.production.local R2_BUCKET | vercel env add R2_BUCKET production
# Set R2_ENDPOINT on the backend project (production)
cw secret-pipe novak-test backend/.env.production.local R2_ENDPOINT | vercel env add R2_ENDPOINT production
# Set R2_ACCESS_KEY_ID on the backend project (production)
cw secret-pipe novak-test backend/.env.production.local R2_ACCESS_KEY_ID | vercel env add R2_ACCESS_KEY_ID production
# Set R2_SECRET_ACCESS_KEY on the backend project (production)
cw secret-pipe novak-test backend/.env.production.local R2_SECRET_ACCESS_KEY | vercel env add R2_SECRET_ACCESS_KEY production
# Set R2_PUBLIC_URL on the backend project (production)
cw secret-pipe novak-test backend/.env.production.local R2_PUBLIC_URL | vercel env add R2_PUBLIC_URL production
# Deploy the backend
vercel deploy --prod
# Run seed:admin against the production database
(set -a; . "$CW_ROOT/clients/backend-novak-test/.env.production.local"; set +a; NODE_ENV=production pnpm seed:admin)
# Run seed:client-site against the production database
(set -a; . "$CW_ROOT/clients/backend-novak-test/.env.production.local"; set +a; NODE_ENV=production PROVISIONING_REQUEST=../novak-test/provisioning-request.json SITE_URL=https://novak-test.realvista.cz pnpm seed:client-site)
# Run seed:client against the production database
(set -a; . "$CW_ROOT/clients/backend-novak-test/.env.production.local"; set +a; NODE_ENV=production TENANT_SLUG=novak-test CLIENT_NAME='Jan Novák' CLIENT_EMAIL=jan.novak@novak-test.cz pnpm seed:client)
# Run seed:site-key against the production database
(set -a; . "$CW_ROOT/clients/backend-novak-test/.env.production.local"; set +a; NODE_ENV=production TENANT_SLUG=novak-test CMS_PROBE_URL=https://admin.novak-test.realvista.cz SITE_KEY_OUT=.env.site-key.production.local pnpm seed:site-key)
cd "$CW_ROOT"
# Move the minted key into the site production file as CMS_API_KEY
cw secret-pipe --write novak-test site/.env.production.local CMS_API_KEY --from-file clients/backend-novak-test/.env.site-key.production.local --delete-source
cd "$CW_ROOT/clients/site-novak-test"
# Set NEXT_PUBLIC_CMS_URL on the site project (production)
printf %s https://admin.novak-test.realvista.cz | vercel env add NEXT_PUBLIC_CMS_URL production
# Set TENANT_ID on the site project (production)
printf %s "$TENANT_ID" | vercel env add TENANT_ID production
# Set CMS_API_KEY on the site project (production)
cw secret-pipe novak-test site/.env.production.local CMS_API_KEY | vercel env add CMS_API_KEY production
# Set REVALIDATE_SECRET on the site project (production)
cw secret-pipe novak-test backend/.env.production.local REVALIDATE_SECRET | vercel env add REVALIDATE_SECRET production
# Deploy the site
vercel deploy --prod
```

- `vercel-env:seed:seed:client-site`: Prints TENANT_ID=<n>; keep it as $TENANT_ID for the site env below.
- `vercel-env:seed:seed:site-key`: M3: the key goes to the file (0600), stdout carries only TENANT_ID and the verification.

- R2 is required in production (the backend config throws without it). Put R2_BUCKET, R2_ENDPOINT, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY and R2_PUBLIC_URL into backend/.env.production.local before the backend env step; one bucket or prefix per client is still to be decided (F16).
- Set MAKLERI_ADMIN_EMAIL in backend/.env.production.local by hand: it is ours, not the client's.
- Order matters: the site build reads the backend, so backend env, deploy and seed come first (F11).

## 16. Fallback addresses (`fallback-domains`)

Attach novak-test.realvista.cz and admin.novak-test.realvista.cz. realvista.cz is on Vercel DNS, so no manual DNS work.

```sh
cd "$CW_ROOT/clients/site-novak-test"
# Attach novak-test.realvista.cz to site-novak-test
vercel domains add novak-test.realvista.cz site-novak-test --scope TEAM
cd "$CW_ROOT/clients/backend-novak-test"
# Attach admin.novak-test.realvista.cz to backend-novak-test
vercel domains add admin.novak-test.realvista.cz backend-novak-test --scope TEAM
cd "$CW_ROOT"
# CNAME novak-test.realvista.cz → cname.vercel-dns.com
vercel dns add realvista.cz novak-test CNAME cname.vercel-dns.com --scope TEAM
# CNAME admin.novak-test.realvista.cz → cname.vercel-dns.com
vercel dns add realvista.cz admin.novak-test CNAME cname.vercel-dns.com --scope TEAM
```

- `fallback-domains:site`: An existing domain answers with a conflict: treat that as done.
- `fallback-domains:admin`: An existing domain answers with a conflict: treat that as done.
- `fallback-domains:record:novak-test.realvista.cz`: Only if Vercel DNS does not already resolve novak-test.realvista.cz for the team's projects.
- `fallback-domains:record:admin.novak-test.realvista.cz`: Only if Vercel DNS does not already resolve admin.novak-test.realvista.cz for the team's projects.
